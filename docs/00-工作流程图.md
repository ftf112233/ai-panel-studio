# 工作流程图（提交物之一）

> 📌 **迭代说明**：本文为设计阶段的工作流图，实现过程中调度环节已由"主持人点名"升级为 **DirectorAgent 自主调度**（举手 / 补充 / 反驳），并新增了阵容生成与确认、实时共识/分歧抽取两个环节；最终流程以 `docs/01-架构设计文档.md` 的迭代说明与代码为准。

## 1. 运行时数据流

```
用户选主题+嘉宾
      │ POST /api/debates
      ▼
创建 Debate(status=created) ──► 前端跳转 #/live/{id} ──► EventSource 连接 SSE
                                                              │
      ┌───────────────────────────────────────────────────────┘
      ▼
Orchestrator.run()
   ├─ OPENING  : HostAgent.decide(opening)      → participants / thinking / delta / focus
   ├─ ROUND r  : 主持人点名 → GuestAgent.speak() 流式 → delta 逐块 → speaker_end → stance
   │            └─ 每轮最多 K 次发言，中途由 HostAgent.decide(next) 决定"追问 / 换人 / 收束"
   └─ SUMMARY  : HostAgent.decide(summary)      → 落库 summary → done
      ▼
每条发言写入 SQLite(messages)；Transcript 侧栏实时同步
```

## 2. 状态机

```
CREATED ──► RUNNING ──► DONE
                │
                └──(顶层异常)──► FAILED ──► 重连后按存档回放

ROUND 内部：
  [Host 聚焦问题] → [Guest 发言] → Host decide → question?→下一个 Guest
                                              → summary/closing?→跳出到 SUMMARY
                                              → 发言数达上限?→进入下一轮（轮数达上限则 SUMMARY）
```

## 3. 开发流程（Git 分支 + 迭代）

```
main
 ├─ feat/skeleton       数据层 + 配置 + Persona 种子
 ├─ feat/llm-stream     DeepSeek 流式客户端 + Mock 降级
 ├─ feat/agents         Host/Guest Agent + 版本化 Prompt + JSON 校验降级
 ├─ feat/orchestrator   状态机 + 调度 + 兜底
 ├─ feat/frontend       四页 UI + SSE 渲染 + Transcript
 └─ docs               设计文档、Prompt 记录、联调实录与 README
```
每次 Prompt 迭代单独一个 commit，对应 `prompts/*.json` 的 `changelog` 一条记录。
