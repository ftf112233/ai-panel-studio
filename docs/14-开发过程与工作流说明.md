# 开发过程思路 & 工作流说明

## 一、我的开发流程：Claude Code（Vibe Coding 工具）× DeepSeek（运行时模型）

我把两者**角色分开**：DeepSeek 是产品里被调用的推理引擎（被调试的对象），Claude Code 是写代码的协作者。

1. **SDD（Schema Driven）阶段**：先让 AI 产出实体/字段/ER 图/API 契约，不写业务代码。这一步的产物是 `docs/11-ER图.md`、`docs/12-API文档.md`，后面所有代码都对着契约长。
2. **DDD（Design Driven）阶段**：把"演播厅视觉与交互约束"翻译成组件与状态机——三个独立滚动面板、专家小窗三种状态、SSE 事件如何驱动状态切换。约束写得越硬，生成的前端越接近可用。
3. **TDD 阶段**：核心逻辑（阵容生成 / 发言调度 / 共识提炼）先写测试跑红，再实现跑绿。测试全部零第三方依赖，用脚本化桩 LLM 模拟"模型返回垃圾 JSON""流式中断"。
4. **E2E 阶段**：subprocess 起服务、urllib 消费真实 SSE，验证"两场讨论并行隔离"这类系统级性质。
5. **闭环**：现场演示暴露的问题（节奏、回放、连接关闭）回到第 3、4 步补测试再改实现。

上下文管理经验：**每个阶段只给 AI 该阶段需要的上下文**（契约阶段不给实现代码，实现阶段给契约 + 测试，不让整仓代码一次性进上下文），这是避免幻觉最有效的手段；同时把 Prompt 与配置外置成版本化 JSON，让"改行为"变成"改数据"。

## 二、与 AI 协同中遇到的三个典型问题

**问题 1：沙箱装不上 fastapi / httpx，交付物有跑不起来的风险。**
解决路径：让 AI 基于同一份 API 契约再产出一份**纯标准库 `http.server` 版服务**（`backend/serve.py`），路由与 SSE 行为等价。收益有二：本地随时可演示；E2E 测试不需要任何依赖也能跑真实 HTTP + SSE。生产路径仍是 `uvicorn + FastAPI`，两条路共用同一套业务代码。

**问题 2：整场讨论 8 秒跑完，"实时感"不成立。（用户现场反馈）**
定位：三个原因叠加——Mock 打字节奏过快；已结束讨论走回放时整条一次灌出；SSE 结束未关闭连接（curl 挂到超时）。
解决：给 MockLLMClient 加 `think_delay / chunk_delay` 两个节奏参数；回放路径改为逐字 + thinking 事件；`serve.py` 在生成器结束后置 `close_connection = True`。实测整场约 60 秒、发言间隔约 5 秒。

**问题 3：异步生成器改造引入静默失败。**
为了让主持人内容逐字流出，我把 `_emit_host` 从同步生成器改成 async generator，但调用处仍是 `for ev in ...`，结果整场直接 `status=failed`、页面只显示 participants。
解决：不是靠肉眼查，而是让 AI 写"状态机必须收敛到 done"的测试第一时间暴露；修正为 `async for` 后 16 个测试全绿。**教训：异步改造必须有行为测试兜底，不能只看类型能编译。**

## 三、我对"工程化 AI 开发"的理解

- **AI 是放大器，不是替代品**：它放大的是"需求是否清晰"。把约束写成可验收的条目（如"相邻发言不能是同一个人""insight 必须早于 done"），AI 才能产出可用的东西；模糊的"做个好看的圆桌"只会产出漂亮的空壳。
- **契约先于代码**：Schema/API/事件协议一旦钉死，实现可以并行、可以重写，甚至可以有两套实现（FastAPI 与 stdlib）。
- **测试是人和 AI 之间的仲裁者**：我不逐行审阅 AI 生成的代码，而是让测试替我判断"行为对不对"。这次两个真 bug 都是测试逼出来的。
- **兜底优先于完美**：所有 LLM 输出都当作不可信输入——JSON 解析失败要降级、调度结果非法要补位、流式中断要补齐。**任何单点失败都不能让直播页面挂掉。**
- **过程可溯 > 一键完美**：Prompt 版本化进 Git、每次迭代写清"为什么改"，交付的是一个能被检验的工程，而不是一段无法追问的生成结果。
