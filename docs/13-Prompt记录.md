# 核心 Prompt 记录（含开发范式阶段标记）

> 作业要求：≥5 段，必须体现多范式阶段性，至少含 SDD / DDD / TDD / E2E 四阶段，每段附说明。
> 说明里的"意图 / 挑战 / 如何修正"是当时的真实过程，不是事后补写。

---

## 【SDD 阶段】Prompt 1：数据建模与 API 契约

**Prompt（原文摘要）**

> 我要做一个 AI 圆桌演播厅 MVP：用户输入话题和专家人数，大模型生成主持人+专家阵容，用户确认后进入演播厅观看实时讨论。数据库用 SQLite。
> 请先不要写代码，只做三件事：
> 1）列出实体（讨论、嘉宾、发言、共识/分歧）与字段，说明为什么阵容要存 JSON 而不是拆表；
> 2）给出 ER 图（mermaid）；
> 3）给出 REST + SSE 的完整 API 契约，SSE 要列出每一种事件的 event 名和 data 结构，尤其是"专家状态小窗"和"实时共识分歧"怎么推。
> 要求：多讨论并行时状态/事件流/transcript/共识必须互相隔离，请说明隔离靠什么字段保证。

**说明**：意图是先把"数据长什么样、前后端说什么话"钉死，避免后面边写边改契约。挑战在于我一开始想把嘉宾拆成独立表，被反问"动态生成的字段演进怎么办"后改成 lineup 存 JSON + 稳定专家 id（`e1..e5`），发言与状态小窗都靠 id 关联——这个决定让后面加"插话""立场漂移"都不用改 schema。

## 【SDD 阶段】Prompt 2：从 API 契约反推 Pydantic 模型与目录结构

**Prompt（原文摘要）**

> 基于上面这份契约，生成 FastAPI 后端目录结构与 Pydantic 模型定义（只写模型与路由骨架，不要实现业务逻辑）。要求：
> - 每个路由一个函数，函数名与契约一一对应；
> - SSE 用 StreamingResponse，事件统一走 `{"event":..., "data":...}`；
> - 同时给我一份等价的"零依赖标准库 http.server 版"骨架，因为我的沙箱装不了 fastapi，需要能离线演示。

**说明**：这一段的价值在于**同一份契约产出两套实现**（FastAPI 生产版 + stdlib 演示版），后来 E2E 测试正是跑在 stdlib 版上。挑战是沙箱 pip 装不上包，我让 AI 保留两套而不是"先装了再说"，避免了交付物在评委机器上跑不起来。

## 【DDD 阶段】Prompt 3：演播厅前端组件与状态流转

**Prompt（原文摘要）**

> 我要一个中文的演播厅界面，有三个约束：
> 1）不依赖整页滚动，舞台区、专家状态区、共识分歧区、Transcript 区各自内部滚动；
> 2）响应式：超宽屏（>1600px）加宽右侧面板，普通桌面左右分栏，窄屏（<1080px）上下堆叠；
> 3）右侧"专家状态小窗"要显示待机/准备发言/发言中三种状态和一句话公开思考摘要，不能显示隐藏 CoT。
> 请给出 HTML 模板 + CSS Grid 布局 + 状态机（前端如何根据 SSE 事件切换每个专家小窗的状态）。不要引入前端框架。

**说明**：意图是让视觉约束反过来驱动组件拆分（这也是作业考察点）。第一版 AI 给的是整页滚动 + 单个 Transcript 抽屉，不满足"区域独立滚动"，我把约束改成显式验收条件重写了一版，才得到现在的 `.studio` Grid + 三个 `.panel` 各自 `overflow-y:auto`。

## 【TDD 阶段】Prompt 4：核心逻辑先写测试

**Prompt（原文摘要）**

> 三个核心逻辑必须先写测试再实现，用 unittest + asyncio，且测试不许依赖网络和第三方库：
> A）阵容生成：模型返回垃圾 JSON 时仍要凑够 N 位专家、颜色不重复、同名要去重；
> B）发言调度：返回的 speaker 必须在座，且不能是上一位发言者；模型总给非法值时要用确定性规则补位，并且三人都要被轮到；
> C）共识提炼：合并去重（归一化比对）、丢弃过短或字段不全的项、列表上限 6 条。
> 请生成测试用例，我会先跑红再实现。

**说明**：跑红后发现两处真实 bug——① 共识去重阈值写成"少于 4 字丢弃"，把合法的中文三字短语也丢了（改成 3 字）；② 调度器补位只看"上一位"，三人场景下会出现某人永远说不上话（改成按发言次数最少者优先）。这两处都是测试逼出来的，不是写代码时想到的。

---

## 【TDD 阶段】Prompt 5：编排器行为约束

**Prompt（原文摘要）**

> 给 Orchestrator 写测试：
> 1）状态机必须收敛到 done，轮次不超过配置上限；
> 2）相邻两次专家发言不能是同一个人（需求明确禁止机械轮流）；
> 3）必须发出 agent_status 事件且带 thought；
> 4）insight 事件必须出现在 done 之前（证明共识是实时更新的，不是结束后补的）；
> 5）单条专家发言长度受控（1-2 句）。
> 桩 LLM 要可以脚本化返回，也要能模拟"流式中断"。

**说明**：意图是用测试把"需求红线"固化成可执行断言。挑战是 Mock 的打字节奏让测试跑了 27 秒，我让 AI 给 MockLLMClient 加上 `chunk_delay/think_delay` 参数，测试里传 0.001/0.01，把整套测试压回可接受范围——这反过来也让"演示节奏"和"测试节奏"可以分别调。

## 【E2E 阶段】Prompt 6：系统级端到端与隔离验证

**Prompt（原文摘要）**

> 写一个零依赖 E2E：subprocess 起 backend/serve.py（stdlib 版，端口 8765），用 urllib 发请求、按行读 SSE，验证：
> 1）样例数据 ≥5 条；2）阵容生成 4 人且颜色不重复；
> 3）**同时创建两场不同话题的讨论，分别消费各自的 SSE，断言事件流/transcript/共识互不相交**（这是需求里的并行隔离）；
> 4）已结束的讨论可回放，且返回完整 transcript 与总结。
> SSE 读到 done 就断开，注意设置超时。

**说明**：这一段的目标是把"隔离性"从口头承诺变成断言。第一版 AI 写的 E2E 用了 requests/httpx（装不上），我明确要求"零依赖、urllib + subprocess"，并强调要起独立端口与独立 DB_PATH，才不会污染开发库。

## 【E2E 阶段】Prompt 7：质量闭环（从现场反馈回到 Prompt）

**Prompt（原文摘要）**

> 现场演示反馈：整场讨论 8 秒就跑完了，看起来像"一下全生成"，不符合演播厅的实时感。请定位原因并修复：
> 1）Mock 客户端的节奏太慢/太快分别调哪个参数；
> 2）已结束讨论的回放路径为什么是整条一次灌出，改成逐字；
> 3）SSE 结束后连接为什么一直挂着不关（curl 会挂到超时），该怎么关；
> 4）主持人内容是"决策 JSON 整体生成后再分块"，如何让它也逐字流出。

**说明**：这是真实的用户反馈闭环——不是改 Prompt 文案，而是改**运行时节奏**和**传输层行为**。修完后实测：整场约 60 秒、每位发言间隔约 5 秒、思考动画停留约 1 秒，回放也逐字播放，SSE 结束即关闭连接。

## 附：运行时 Prompt（产品内使用，非开发用）

产品内实际调用大模型的 5 类 Prompt 全部版本化管理在 `backend/prompts/`：

| 文件 | 版本 | 作用 | 迭代要点 |
|---|---|---|---|
| `lineup.v1.json` | v1 | 动态生成主持人+专家阵容 | 要求立场互相对立、身份具体到可反驳 |
| `host.v5.json` | v1→v5 | 开场/串联/追问/插话/总结 | v3 强制引用嘉宾真实发言（收益最大）、v5 限 1-2 句并加插话 |
| `director.v1.json` | v1 | 自主调度（举手/补充/反驳）+ 公开思考摘要 | 显式禁止机械轮流、禁止连续同一人 |
| `guest.v4.json` | v1→v4 | 专家短发言 + 立场漂移 | v3 加 stance_shift、v4 压缩到 1-2 句 |
| `insight.v1.json` | v1 | 增量提炼共识与分歧 | 只提炼增量、无新增返回空数组 |

每份文件都带 `changelog` 字段，记录每次迭代的原因，随代码进 Git。
