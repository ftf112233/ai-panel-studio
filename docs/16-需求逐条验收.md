## 五、开发过程中真实修掉的缺陷

1. **共识/分歧出现占位词**：`insight.v1.json` 未传说话人 → 输出"发言者 vs 尚未表态的其他人"。改为模板带 `{speaker}` + 硬性要求真实姓名（`docs/15-真实联调实录.md` 实录二已验证）。
2. **异步生成器调用遗漏**：`_emit_host` 改 async generator 后调用处仍是 `for`，导致整场 `status=failed`；由"状态机必须收敛到 done"的测试第一时间暴露。
3. **调度补位只看上一位**：三人场景下有人永远轮不到；改为按发言次数最少者优先。

## 六、后续改进方向

- 调度策略实验：自主调度 vs 点名制的 A/B 对比（固定 3 主题 × 每种 3 次，按交锋率 / 重复率 / 聚焦度 / 收敛性 / 立场真实性 / 人设一致性 6 指标人工打分）
- 共识/分歧的多轮投票式聚合与置信度
- 事件表 + Last-Event-ID 断点续传（当前靠 SSE 重放）
- 观众中途提问 / 指定下一位发言人
- LLM 调用可观测性（token / 耗时 / 降级率看板）
